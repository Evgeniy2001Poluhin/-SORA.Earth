## Что делает инструмент

```bash
python3 ieg_join.py <CSV_IEG> <каталог_документов> <новая_выходная_папка>
```

1. Каталог: `manifest.json` должен быть JSON-объектом с целыми `documents`,
   `with_project_id`, 64-символьным `csv_sha256` и `contains_outcome_ratings: false`.
   SHA-256 `documents.csv` сверяется с манифестом; число строк — с `documents`;
   ID документов должны быть непустыми и уникальными; число документов с
   project ID — с `with_project_id`. Колонки `id`, `projectid` обязательны и
   не должны повторяться.
2. В каталоге `projectid` может быть списком через запятую (совместные
   операции): такой документ засчитывается каждому проекту списка, а эти
   проекты помечаются `document_shared_with_other_projects`.
3. CSV IEG: обязательный минимум — по одной колонке `project_id` и `outcome`
   (после нормализации: `Project ID`, `project_id`, `PROJECTID` — одно и то же).
   ID обрезается по пробелам и приводится к верхнему регистру. Рейтинги
   остаются исходной шкалой IEG (`satisfactory`, `not rated`, `missing`,
   `unrecognized` и т. д.); неизвестные значения перечисляются со счётчиками.
4. Сопоставление только по project ID. Ни одна строка не удаляется и не
   выбирается: дубликаты IEG, проекты с несколькими документами и проекты в
   общих документах выгружаются в `ambiguous-groups.csv` для ручного разбора.
5. Выход: `coverage-report.json` (агрегаты, контрольные суммы обоих входов и
   манифеста, имена файлов без путей) и `ambiguous-groups.csv`
   (`project_id, ieg_rows, catalog_documents, reasons`). Текст рейтингов,
   названия и ссылки в CSV групп не попадают.
6. `as_of_date`, `evaluation_fy`, `approval_fy`, `final_closing_fy` и `docdt`
   не используются; отчёт лишь отмечает, какие из них есть в CSV, и прямо
   пишет, что это не даты первой публикации и не даты доступности признаков.

Отказы (код возврата 1, JSON `{"join_passed": false, "reason_code": ...}`,
ничего не записывается): `manifest_invalid_json`, `manifest_bad_*`,
`manifest_must_declare_no_outcome_ratings`, `catalog_sha256_mismatch`,
`catalog_document_count_mismatch`, `catalog_duplicate_document_id`,
`catalog_empty_document_id`, `catalog_with_project_id_mismatch`,

## Оставшиеся ограничения

- Формат официального CSV неизвестен. Адаптер принимает только колонки,
  нормализующиеся в `projectid` и `outcome`. Заголовок вроде `IEG Outcome`
  или `Outcome Rating` будет отказом `ieg_csv_missing_or_ambiguous_columns`;
  понадобится явное сопоставление колонок, а не угадывание.
- Шкала проверяется по шести стандартным рейтингам и `Not Rated`; варианты
  написания и иные шкалы попадут в `unrecognized` и требуют ручного решения.
- Совпадение project ID не доказывает, что документ — та самая оценка, на
  которой основан рейтинг, и что рейтинг — последняя версия. Совместные
  операции (как P161490/P157521 в `ИСТОЧНИК-ИСХОДОВ.md`) не независимы.
- Подлинность CSV IEG инструмент не удостоверяет: фиксируется только SHA-256.
- Каталог содержит только отчёты типа ICR Review, 1998–2025; проекты без
  такого отчёта покажутся «отсутствующими в каталоге», это не значит, что
  оценки нет.
- Даты не проверяются и не используются; временной протокол не построен.
