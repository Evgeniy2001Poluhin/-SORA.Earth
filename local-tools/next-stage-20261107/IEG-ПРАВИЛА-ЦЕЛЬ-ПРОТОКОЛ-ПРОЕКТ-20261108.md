## 2. Предлагаемые правила

**П1. Повтор строки IEG.** Если исходные рейтинги одинаковы — у проекта одна
оценка на уровне проекта, строки не удаляются, выбор «последней» не нужен для
метки. Если различаются — проект исключается до ручного решения. Сейчас:
P122764, обе «Moderately Satisfactory» (Evaluation FY 2023 и 2026) — по П1
рейтинг однозначен; год, когда он стал известен, не определён (2023 или
раньше), поэтому для временного протокола берётся консервативно поздний — 2026.

**П2. Общий документ (кластер).** Проекты одного ICR Review — совместная
операция, не независимые наблюдения. Кластер — единица разбиения: все его
проекты целиком в train или целиком в test, в метриках считается одной
единицей (или с весом 1/размер). Кластер с расходящимися рейтингами (5:
P004850, P070560, P073113, P074014, P074801 по наименьшему ID) исключается
до ручного решения.

**П3. Тип оценки отличается от документа.** Для PPAR рейтинг взят из более
позднего аудита, а документ в каталоге — более ранний ICR Review. Рейтинг
можно использовать как исход, но документ и его `docdt` не являются
свидетельством этого рейтинга. Для первой версии набора предлагается брать
только ICRR, PPAR — отдельной проверкой устойчивости.

**П4. Несколько документов у проекта.** Документ не выбирается: для метки он
не нужен (рейтинг на уровне проекта), а `docdt` не используется как дата.

**П5. Not Rated / пусто / нераспознанное** — не исход, исключается из
оценочной выборки, но учитывается в отчёте (151 строка Not Rated во всей выгрузке).

## 3. Цель — варианты на выбор

- **А (рекомендую как основную).** Бинарная: «удовлетворительно» =
  Moderately Satisfactory и выше; «неудовлетворительно» = Moderately
  Unsatisfactory и ниже. Это граница, которую использует сам IEG в сводных
  долях; порог фиксируется до просмотра метрик.
- **Б.** Порядковая шкала из 6 уровней (без бинаризации), метрика — ранговая.
- **В.** Строгая: Satisfactory и выше против остального — меньше баланс,
  чувствительнее к смещению шкалы во времени.

Важно: это **исход проекта Всемирного банка по оценке IEG**, а не «ESG-успех»
SORA. Переименовывать его в ESG-показатель нельзя без отдельного решения.

## 4. Признаки — главный нерешённый вопрос

В выгрузке IEG **нет** признаков, на которых обучена модель SORA (budget,
co2_reduction, social_impact, duration_months и производные). Из самой
выгрузки допустимы только известные на момент одобрения: WB Region,
Country / Economy и его группы, Practice Group, Global Practice, Agreement
Type, Lending Instrument Type, Approval FY.

**Запрещены как признаки** (известны только при/после оценки — утечка):
Quality at Entry, Quality of Supervision, Bank Performance, M&E Quality,
Final Closing FY, Evaluation FY, Evaluation Type, As of Date. Длительность
проекта (Final Closing − Approval) — тоже утечка (см. память проекта о
`duration_months`). Бюджет и другие числовые признаки потребуют отдельного
источника (Projects API) с доказанной датой доступности.

## 5. Временной протокол (предложение)

Точных дат нет, только финансовые годы, поэтому протокол консервативный:

- момент прогноза — Approval FY проекта;
- исход считается известным не раньше конца Evaluation FY;
- граница T: test — проекты с Approval FY ≥ T; train — только проекты с
  Evaluation FY ≤ T − 1 (строго раньше, целый FY запаса);
- кластеры П2 не разрезаются; если члены кластера попадают по разные стороны
  границы, кластер целиком уходит в более позднюю сторону или исключается;
- T выбирается до любых вычислений метрик. Объёмы только счётчиками, по
  5 786 однозначным ICRR-проектам с рейтингом (без Not Rated), без обучения:

  | T | train (Eval FY ≤ T−1) | test (Approval FY ≥ T) | не используются |
  |---|---|---|---|
  | 2012 | 2 569 | 1 370 | 1 847 |
  | 2014 | 2 948 | 971 | 1 867 |
  | 2016 | 3 586 | 531 | 1 669 |

  Около трети проектов попадает в зазор при любом T — это цена протокола
  по финансовым годам. Предлагаю T = 2014;
- нижний ориентир качества — частота класса и простая модель по региону/
  практике; итоговая метрика — с доверительным интервалом.

## 7. План оценки базовой модели — зафиксирован 9 ноября 2026 до запуска на данных

Владелец разрешил обучение 9 ноября 2026 («Да, обучай»). Всё ниже записано до
первого прогона на реальных данных; любое изменение после просмотра метрик test
отчитывается как post hoc, а не заменяет этот план.

- **Модели.** M0 — константа, равная доле успехов в train. M1 — простая:
  регион и Practice Group. M2 — полная: страна, регион, Agreement Type, Lending
  Instrument Type, Practice Group, Global Practice.
- **Approval FY не используется** ни в одной модели: в train и test он не
  пересекается, как категория бесполезен, как число — экстраполяция тренда.
- **Кодирование** — one-hot, словарь строится только по train; пустое значение
  и значение, которого нет в train, дают нулевой вектор.
- **Алгоритм** — логистическая регрессия, C = 1.0, без подбора гиперпараметров
  и без взвешивания. Метки test в обучении не участвуют.
- **Основная метрика** — ROC AUC на test. Доверительный интервал 95% —
  бутстреп по кластерам П2 (кластер — единица пересэмплирования), 2 000
  повторов, seed 20261109.
- **Дополнительно** — Brier score, его улучшение относительно M0 (Brier skill
  score) с тем же бутстрепом, log loss, разность AUC M2 − M1 (парный бутстреп),
  средний прогноз против фактической доли успехов в test.
- **Правило решения.** Модель лучше базовой линии, только если нижняя граница
  95% интервала AUC выше 0.5 **и** нижняя граница интервала Brier skill score
  выше 0. Иначе результат — «не лучше частоты класса».
- Прогон один. Результат записывается, каким бы он ни был.

**Результат (9 ноября 2026):** ни M1, ни M2 не лучше частоты класса — AUC 0.52
(ДИ включает 0.5), Brier skill отрицателен. Подробности — дополнение 5 отчёта.

## 9. Показатели страны до одобрения — план зафиксирован 9 ноября 2026 до запуска

Владелец 9 ноября 2026: «продолжай работу» — следующий источник из дополнения 6.

**Источник:** World Development Indicators, API `api.worldbank.org/v2`, снимок
с манифестом и SHA-256. Страна проекта — `countrycode` из снимка Projects API
(ISO2); код, которого нет в WDI (региональные проекты), — пропуск.

**Кандидаты:** рост ВВП (NY.GDP.MKTP.KD.ZG), log10 ВВП на душу в постоянных
долларах (NY.GDP.PCAP.KD), инфляция (FP.CPI.TOTL.ZG; признак — знаковый
log10(1 + |x|)), эффективность правительства WGI (GOV_WGI_GE.EST, источник 3; код GE.EST API отклонил), CPIA IRAI
(IQ.CPA.IRAI.XQ).

**Год значения:** календарный год Approval FY − 2. FY N кончается 30 июня N,
значение за год N − 2 публикуется к середине N − 1, то есть до одобрения.
Оговорка: в снимке — текущие ревизии значений, а не те, что были доступны
тогда.

**Правило отбора, применяется до просмотра исходов:** кандидат допускается,
только если его заполненность ≥ 70% в train и в test и различается между ними
не больше чем на 10 процентных пунктов. Иначе признак узнаёт эпоху по
пропускам (так было с флагами пропуска в M4).

**Модели:** M5 — регион + Practice Group + допущенные показатели страны; M6 —
только допущенные показатели. Кодирование, алгоритм, бутстреп, правило
решения — как в разделах 7–8. Разность AUC M5 − M1.

**Оговорка:** это третий взгляд на тот же test. Положительный результат около
границы считается неубедительным; окончательную проверку даст только новый
test — оценки IEG, опубликованные после 9 ноября 2026.

**Результат (9 ноября 2026):** допущены рост ВВП, ВВП на душу, инфляция; WGI и
CPIA отклонены правилом. M5 AUC 0.530 — не лучше; M6 AUC 0.550 (ДИ 0.501–0.596),
Brier skill ДИ включает 0 — не лучше по правилу, пограничный, неубедительный.
Подробности — дополнение 7 отчёта.
