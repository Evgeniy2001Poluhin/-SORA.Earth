# Задание Claude Code: проверяемое сопоставление IEG и каталога документов

Работай только в текущем worktree. Пользователь попросил передать выполнение
Claude, а GPT затем проверит отчёт. Лимиты обновлены. Ответ и отчёт на русском.

## Цель

Подготовь локальный инструмент для проверки сопоставления будущего
официального CSV с оценками проектов IEG и уже сохранённого каталога
отчётов World Bank. Официального CSV оценок пока нет. Работай на
синтетических фикстурах; настоящий источник не выдумывай и не скачивай в
обход условий сайта. Каталог `wb-documents-20261107` содержит только
метаданные 7 303 отчётов и не является набором меток.

Входные материалы:

- `local-tools/next-stage-20261107/profile_ieg.py`
- `local-tools/next-stage-20261107/outcomes.py`
- `local-tools/next-stage-20261107/wb-documents-20261107/manifest.json`
- `local-tools/next-stage-20261107/wb-documents-20261107/documents.csv`
- `local-tools/next-stage-20261107/ИСТОЧНИК-ИСХОДОВ.md`

## Результат

Создай отдельный CLI в `local-tools/next-stage-20261107/`, который принимает
путь к оператором скачанному CSV IEG, путь к каталогу документов и путь к
новой выходной папке. Он проверяет SHA-256 каталога и его число/уникальность
документов, а затем строит только агрегированный отчёт покрытия по project ID.
Сохраняй дубликаты IEG и группы нескольких документов одного проекта для
ручного разбора, не выбирая за оператора «правильную» строку. В отчёте должны
быть число строк и уникальных ID IEG, число совпавших ID, число отсутствующих
ID с каждой стороны, группы с несколькими оценками и с несколькими
документами, пустые ID, неизвестные значения outcome и контрольные суммы
исходных файлов. Для групп с неоднозначным сопоставлением можно вывести
отдельный CSV только с ID и количествами. Исходные рейтинги не превращай в
бинарные метки. `as_of_date`, `evaluation_fy` и `docdt` нельзя представлять
точной датой первой публикации или доступности признаков.

Инструмент должен отказывать на битом манифесте, пустом/нечитаемом файле,
неоднозначных обязательных колонках, неправильных строках и попытке
перезаписать готовый выходной каталог. Никаких паролей, ключей, персональных
данных, GitHub/прода или сетевых запросов.

Напиши небольшие содержательные тесты с фикстурами. Проверь положительный
случай, дубликаты и по одному отрицательному случаю для повреждённого каталога
и CSV. Не дублируй всю реализацию в тестах. Запусти их и один запуск на
синтетическом CSV; настоящий набор оценок не заявляй проверенным.

Запиши итог в `local-tools/next-stage-20261107/CLAUDE-IEG-JOIN-REPORT-20261108.md`.
Включи список файлов, команды и результаты, пример агрегированного вывода,
ошибки, оставшиеся ограничения и точный следующий шаг после получения
официального CSV. Отдельно укажи, что обучение/валидация модели не запускались.

## Границы

Не трогай запущенное 24-часовое задание MSI, резервные копии, расписания,
PR 524, production, `.deploy-blocked`, ветки и stash. Не коммить и не пушь.
Не задавай пользователю вопросов; если формат официального CSV неизвестен,
сделай адаптер по уже принятому минимуму `project_id` и `outcome`, явно
описав ограничения. Заверши работу после тестов и отчёта, не запускай
неограниченные циклы и тяжёлые общие тесты.
